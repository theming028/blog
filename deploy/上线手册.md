## 已知性能特征：跨境延迟

服务器在新加坡，中国大陆访问者要承担跨境链路开销。实测：

- **服务器自身**：`/api/posts` 0.18s、`/js/feed.js` 0.04s，连续 10 次请求 10/10 成功；
- **跨境访问**（从境内机器观察）：单个资源 1.3–6s，整页信息流首次渲染 15–45s，且约 1/3 的访问在 30–50s 内取不到帖子数据——服务端日志显示请求都到了且返回 200，瓶颈在链路丢包/抖动。

曾怀疑 nginx 的 HTTP/2 是主因（单连接多路复用在丢包链路上会阻塞所有流），但各 3 次的 A/B 基线**推翻了它**：H2 与强制 HTTP/1.1 成功率同为 2/3。因此 `http2 on;` 保持不动，改它没有依据。

若境内体验重要，可选：① 套 CDN（改善明显，但域名走 CDN 仍受备案规则约束）；② 换中国大陆节点并完成 ICP 备案（延迟最低，需 1–22 个工作日）；③ 接受现状（免备案的代价）。

## 更新代码

```bash
tar -czf blog.tgz -C <项目目录> --exclude=.git --exclude=data/.DS_Store \
    --exclude=tools-pull-live-data.js --exclude=deploy .
scp -i <key> blog.tgz root@47.79.249.10:/root/
ssh -i <key> root@47.79.249.10 \
  'cd /opt/blog && tar -xzf /root/blog.tgz --exclude=./data/db.json && chown -R blog:blog /opt/blog && systemctl restart blog'
```

`--exclude=./data/db.json` 很关键：服务器上的 `db.json` 会持续积累访客与评论，覆盖它会丢数据。
