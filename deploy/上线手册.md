## 备案下号后做什么

一条命令完成签发 + 切 HTTPS + 自检：

```bash
ssh root@47.109.22.191 '/root/deploy/_cutover.sh --confirmed'
```

`--confirmed` 必须带：阿里云的拦截只作用于从公网进入的流量，**在服务器上自测域名会绕过拦截拿到 200，必然假绿**（第一版脚本栽在这里）。不带该参数脚本会在签发前停下，不消耗 Let's Encrypt 每周 5 张的重复签发配额。

## 为什么换到内地节点

跨境链路是上一台（新加坡 `47.79.249.10`）慢的根因，实测本机 TCP 建连中位数：

| 目标 | RTT |
| --- | --- |
| 新加坡节点 | ≈ 400ms（样本 0.39–1.42s，含丢包重传） |
| **成都节点** | **≈ 11ms**（样本 8–15ms） |
| 国内参照 www.aliyun.com | ≈ 8ms |

浏览器实测整页：冷启动首帖从 13.5–32.7 秒降到 **0.40 秒**，回访 **0.31 秒**（34 个资源 28 个命中缓存、仅传 13KB）。

配合代码层的优化（资源内容哈希版本号 + 一年 immutable、封面头像服务端注入、启动请求并行化、图片/字体长缓存、Nginx 连接复用），回访几乎零传输。参见提交 `26a5c1f`。

## 已加固的三项

### 1. 备案期间关闭按 IP 访问

`/etc/nginx/conf.d/00-default-deny.conf`：凡 Host 不是 `shaoym.me`/`www.shaoym.me` 的请求（裸 IP、
伪造 Host、扫描）一律 444 断开；443 用 `ssl_reject_handshake on` 在握手阶段断开，不需要证书。

验证：`Host: shaoym.me` → 200；裸 IP 与伪造 Host → 连接被断；外部按 IP → 打不开。

**代价**：备案下号前你无法从任何途径预览站点（域名被阿里云拦、IP 被本地关）。这是「首次备案期间
网站须关闭」要求的直接后果。要临时恢复预览：把该文件从 `conf.d` 挪走再 `systemctl reload nginx`。

### 2. 每日备份 `db.json`

`/usr/local/bin/blog-backup.sh`，cron 每日 04:10。保留用**固定 14 个槽位按日轮转覆盖**
（`/var/backups/blog/db-slotNN.json.gz`），不用 `find -delete`——保留期同样有界，但误配 cron
也不会把历史清空。每次备份后校验 gzip 完整性并真的解析成带 posts 数组的 JSON，失败写
`/var/log/blog-backup.log` 并返回非零。

**局限**：备份与原库在同一块盘。上一台新加坡实例整机释放时，机内备份会一起没了。
建议后续同步到机外（OSS 或另一台服务器）。

### 3. SSH 仅密钥登录

`/etc/ssh/sshd_config.d/99-keyonly.conf`：`PasswordAuthentication no` +
`PermitRootLogin prohibit-password` + `MaxAuthTries 3`。已双向验证：新密钥会话可登录，
口令认证被拒（服务端认证方式列表里已无 `password`）。

**重要**：目前 `authorized_keys` 里**只有一把我用的部署密钥**（在本机
`~/.qwenworkcn/tmp/tmb-deploy/deploy_key`）。请尽快加上你自己的公钥，否则那台 Windows
机器出问题你就只能走阿里云控制台的 VNC（用系统口令，不受此配置影响）：

```bash
# 在你自己的机器上执行，把公钥追加进去
cat ~/.ssh/id_ed25519.pub | ssh -i deploy_key root@47.109.22.191 \
  'install -d -m 700 /root/.ssh && cat >> /root/.ssh/authorized_keys && chmod 600 /root/.ssh/authorized_keys'
```

撤销：把 `99-keyonly.conf` 挪出该目录后 `systemctl reload sshd`。

## 更新代码

```bash
tar -czf blog.tgz -C <项目目录> --exclude=.git --exclude=data/.DS_Store \
    --exclude=tools-pull-live-data.js --exclude=deploy .
scp -i <key> blog.tgz root@47.109.22.191:/root/
ssh -i <key> root@47.109.22.191 \
  'cd /opt/blog && tar -xzf /root/blog.tgz --exclude=./data/db.json && chown -R blog:blog /opt/blog && systemctl restart blog'
```

`--exclude=./data/db.json` 很关键：服务器上的 `db.json` 持续积累访客与评论，覆盖会丢数据。
