## 二、系统构成

网站为**单一应用 + 反向代理**的两层结构，不使用第三方 SaaS、无外部数据库、无内容分发网络：

| 层次 | 组件 | 版本 | 职责 |
| --- | --- | --- | --- |
| 接入层 | Nginx | 1.30.4 | 监听 80/443，TLS 终止，静态资源缓存与压缩，反向代理到本机应用 |
| 应用层 | Node.js + 自研应用（`moments-blog`） | Node v22.14.0 | 页面渲染、内容存储、评论审核、访问统计 |
| 数据层 | 单文件 JSON 存储（`/opt/blog/data/db.json`） | — | 文章、评论、点赞、图片（Base64 内嵌）、设置、访问日志 |

**应用无第三方运行时依赖**（不使用 npm 依赖包），依赖面仅限 Node.js 官方运行时与 Nginx，
因此不存在因上游开源包被投毒或长期未维护引入的风险；升级路径为替换 Node 二进制与部署自身代码。

## 三、网络拓扑

```
                     互联网用户
                         │
              HTTPS 443 / HTTP 80（仅用于 301 跳转与证书校验）
                         │
        ┌────────────────▼─────────────────┐
        │  阿里云轻量服务器 47.109.22.191   │
        │  ── 云侧防火墙：仅放行 22/80/443 ──│
        │                                  │
        │  ┌────────────────────────────┐  │
        │  │ Nginx 1.30.4（root 运行）   │  │
        │  │  · TLS 终止（Let's Encrypt）│  │
        │  │  · 非本站域名请求 → 直接断开 │  │
        │  │  · 上传体积上限 20 MB       │  │
        │  │  · 静态资源 gzip 压缩       │  │
        │  │  · 透传真实来源 IP          │  │
        │  └─────────────┬──────────────┘  │
        │                │ 仅 127.0.0.1:8081│
        │  ┌─────────────▼──────────────┐  │
        │  │ Node 应用（特权分离）        │  │
        │  │  · 专用非登录用户 blog       │  │
        │  │  · 仅监听 127.0.0.1（不对外）│  │
        │  │  · systemd 沙箱加固          │  │
        │  └─────────────┬──────────────┘  │
        │                │                 │
        │  ┌─────────────▼──────────────┐  │
        │  │ /opt/blog/data（权限 750）  │  │
        │  │  db.json  仅 blog 用户可写  │  │
        │  └────────────────────────────┘  │
        │                                  │
        │  每日 04:10 备份 → /var/backups/blog（14 份轮转）
        └──────────────────────────────────┘
```

**要点**

1. 应用进程**只监听 `127.0.0.1:8081`**，不对公网暴露端口；所有外部访问必须经过 Nginx。
2. Nginx 对 Host 不属于本站域名的请求（直接访问 IP、伪造 Host）在连接层直接断开，
   443 端口在 TLS 握手阶段即拒绝，未备案/探测流量无法到达应用。
3. 云侧另有阿里云轻量服务器控制台防火墙，仅放行 22、80、443 三个端口。
4. 应用以专用系统用户 `blog` 运行，该用户 shell 为 `/sbin/nologin`，不可交互登录；
   仅 `/opt/blog/data` 目录对其可写，系统目录以只读方式挂载（`ProtectSystem=full`）。

## 四、对外服务与数据流

| 数据流 | 说明 |
| --- | --- |
| 页面与静态资源 | 同源提供，`connect-src 'self'` 限制前端只能与本站通信 |
| 图片 | 站内图片由应用从数据库读出并以 `/api/images/<id>` 提供，缓存一年 |
| 音视频 | **本站不托管媒体文件**，仅存储作者填写的 https 外链地址，由用户浏览器直接向源站请求 |
| 外部链接 | 页脚友情链接指向第三方站点，均带 `rel="noopener nofollow"`；仅管理员可添加 |
| 管理后台 | `/admin`，需口令登录，会话 Cookie 为 HttpOnly + SameSite=Lax + Secure |

## 五、访问控制与运维通道

| 通道 | 控制措施 |
| --- | --- |
| SSH（22） | **仅密钥认证**，已关闭口令认证；`PermitRootLogin prohibit-password`；`MaxAuthTries 3`；`LoginGraceTime 20s` |
| 管理后台 | 账号口令登录；连续 5 次失败触发登录锁定；会话 7 天滑动过期，登录成功即换发新令牌（防会话固定） |
| 应用进程 | 非特权用户运行，systemd 沙箱（`NoNewPrivileges`、`PrivateTmp`、`ProtectHome`、`ProtectSystem=full`），异常退出 3 秒自动重启 |
| 数据文件 | 权限 `750`，属主 `blog:blog`，其它账号不可读 |
| 日志 | Nginx 访问/错误日志、systemd journal 应用日志，由 logrotate 轮转 |

> 说明：该云主机镜像默认关闭 SELinux，主机层强制访问控制未启用。作为补偿，
> 采用了非特权服务账号 + systemd 沙箱指令 + 应用仅监听回环 + 云侧与主机双层端口限制 + 仅密钥登录。
> 后续如启用 SELinux，将同步更新本说明。
