## 一、适用范围

本预案适用于本站发生的下列网络安全与信息内容突发事件：
网站无法访问或服务中断；页面被篡改或被植入违法不良信息、木马、挖矿脚本；
发生大规模垃圾评论或刷屏攻击；遭遇拒绝服务攻击或恶意扫描；
管理口令泄露、会话被劫持；服务器被入侵或数据被窃取、篡改、丢失。

## 二、事件分级

| 级别 | 判定标准 | 响应要求 |
| --- | --- | --- |
| Ⅰ 特别严重 | 网站被劫持挂马、发布涉政涉黄等严重违法信息、用户数据大规模泄露、长时间完全不可访问 | **立即处置并即时报属地公安机关网安部门**，全程保存证据 |
| Ⅱ 严重 | 单条或少量违法不良信息公开发布、后台口令疑似泄露、持续大流量攻击导致明显卡顿或间歇不可用 | 2 小时内完成先期处置，24 小时内视情报告 |
| Ⅲ 一般 | 垃圾评论批量出现、个别内容被举报、证书即将过期、备份失败、局部功能异常 | 24 小时内处置完毕并记录 |

## 三、处置流程

```
发现（监控告警 / 用户举报 / 上级通知 / 日常巡查）
   ↓
先期遏制  ── 停止传播、断开受影响服务、封禁来源
   ↓
取证留存  ── 保存日志、被篡改页面快照、涉事内容与来源 IP、时间线
   ↓
分析定级  ── 判定级别与影响范围
   ↓
清除恢复  ── 清理违规内容 / 重装或回滚 / 从校验通过的备份恢复数据
   ↓
复核验证  ── 确认恢复正常、无残留、无二次风险
   ↓
报告归档  ── Ⅰ/Ⅱ 级向属地公安机关网安部门报告；全部事件形成处置记录留存
```

## 四、可直接执行的处置手段（本站实际可用命令）

以下手段已在服务器上验证可用，负责人或应急联络人可立即执行。

### 1. 紧急关停网站（最快速的止损手段）

```bash
# 整站下线（保留服务器，仅停止对外服务）
systemctl stop blog

# 或只关内容、保留服务：将 Nginx 指向"维护中"页面
cp /root/deploy/00-default-deny.conf /etc/nginx/conf.d/00-default-deny.conf && systemctl reload nginx
# 该配置对非本站域名的请求直接断开；如需连本站域名一并拒绝，
# 可临时把 shaoym.me.conf 的 location / 改为 return 403;
```

### 2. 屏蔽单条违规内容

登录管理后台 `/admin` → 评论管理 → 将该内容状态置为「屏蔽」，即刻从公开页面移除，
无需删除，保留记录用于取证。

### 3. 封禁攻击来源

```bash
# 查看高频来源
tail -n 5000 /var/log/nginx/access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head
# 在阿里云轻量控制台防火墙中封禁对应来源 IP（推荐，云侧拦截不消耗主机资源）
```

### 4. 口令与会话泄露处置

```bash
# 修改服务器 root 口令（口令认证已关闭，同时更新对应公钥）
passwd root
# 更换 SSH 密钥后重启服务，使旧会话失效
systemctl restart sshd
```
管理后台口令需同步更换；应用会话为内存态令牌表，重启应用即全部失效：
```bash
systemctl restart blog
```

### 5. 数据恢复

```bash
ls -la /var/backups/blog/                    # 查看可用备份（14 个槽位，含校验记录）
tail -5 /var/log/blog-backup.log             # 确认最近一次备份校验通过
gzip -t /var/backups/blog/db-slotNN.json.gz  # 恢复前再次校验完整性
systemctl stop blog
gzip -dc /var/backups/blog/db-slotNN.json.gz > /opt/blog/data/db.json
chown blog:blog /opt/blog/data/db.json && chmod 640 /opt/blog/data/db.json
systemctl start blog
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: shaoym.me' http://127.0.0.1/   # 期望 200
```

### 6. 取证与留存

```bash
mkdir -p /root/incident/$(date +%Y%m%d-%H%M)
cd /root/incident/$(date +%Y%m%d-%H%M)
cp -a /var/log/nginx/access.log* /var/log/nginx/error.log* . 2>/dev/null
journalctl -u blog --since "3 days ago" > blog.log
curl -s -H 'Host: shaoym.me' http://127.0.0.1/ > page-snapshot.html   # 被篡改页面现场快照
sha256sum * > checksums.txt                                            # 证据完整性固定
```
证据文件不得修改，处置完成后连同时间线记录一并归档，保存期限不少于 6 个月。

## 五、报告与联络

1. **报告对象**：属地公安机关网安部门（四川省成都市，具体受理单位与联系电话见备案平台回执）。
2. **报告时限**：Ⅰ 级事件立即报告；Ⅱ 级事件处置后 24 小时内报告；
   发生个人信息泄露、毁损、丢失的，依法**及时告知用户并向主管部门报告**。
3. **报告内容**：事件发生时间、发现途径、影响范围（涉及信息类别与人数）、已采取的措施、
   当前状态、下一步计划、联系人及联系方式。
4. **配合义务**：留存相关网络日志与证据，配合公安机关调查，不得删除、篡改相关记录。
